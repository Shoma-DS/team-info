# Remotion Short Sound Design

## 使う場面
- 縦ショート動画に効果音を追加する。
- 台本ごとに背景画像や挿絵を変え、毎回同じ素材の使い回しを避ける。
- 台本から必要な画像を考え、フリー素材・イラスト素材・画像生成のどれを使うか判断する。
- テロップ変更や場面転換に合わせて画像や効果音を増やし、テンポを上げる。
- 改行位置、タイトル位置、字幕位置、画像余白をテンプレ別の採点基準でチェックする。
- ユーザーの追加指示をテンプレ別基準へ蓄積し、次回以降の判断に使う。

## 必須フロー
1. 対象 Composition とテンプレートを特定する。
2. テンプレート別基準を読む。縦ショート汎用は `references/templates/viral-short-vertical.md`。
3. 台本を読み、フック・各章・CTAごとに「必要な画像の役割」を決める。
4. 既存素材の使い回し率を確認し、同じ素材が続く場合は新規素材を用意する。
5. 画像ソースを選ぶ。素材サイトで十分ならフリー素材/イラストを使い、台本固有の場面が必要なら画像生成を使う。
6. 画像を `Remotion/my-video/public/viral/<project>/` に保存し、用途が分かる英数字名にする。
7. 画像を縦ショートの画面バランスに合わせて表示する。必要なら `objectFit`、`objectPosition`、`visuals` の切替フレーム、拡大率を調整する。
8. 効果音の候補を選ぶ。ビジネス系ショートでは、過剰にゲーム音へ寄せず、短い見出し音・場面転換音・軽い衝撃音を優先する。
9. 効果音を `Remotion/my-video/public/audio/<project>/sfx/` に保存し、用途が分かる英数字名にする。
10. Remotion 側は `visuals` と `sfx` のタイムライン配列で管理し、各 `<Sequence>` に `name` を付ける。
11. `npm --prefix "$TEAM_INFO_ROOT/Remotion/my-video" run typecheck` を実行し、代表 still を再取得して確認する。

## 画像設計ルール
- 毎回、台本の意味から画像案を作る。既存テンプレ画像をそのまま反復しない。
- フック、各章、CTAで最低1枚ずつ役割の違う画像を用意する。本文が長い章では句点単位で2-5枚の切替を検討する。
- 画像案は「誰が/どこで/何をしている/どんな感情か」を短く定義してから探す。
- 転職・仕事系では、オフィス、面談、履歴書、スマホ求人検索、疲れた通勤、上司との距離感、メモを書き出す手元など、台本の行動に合う具体場面を優先する。
- 見たことがある素材ばかりに見える場合は、構図を変える。例: 正面の人物ではなく、手元、背中、俯瞰、机上、ガラス越し、夜のデスクなど。
- 同じ動画内で同じ画像を短時間に反復しない。同じテーマでも、イラスト/写真/手元/俯瞰など視点を変える。
- 写真とイラストを混ぜる場合は、色味と余白を合わせ、急に別世界に見えないようにする。

## 並列化・サブエージェント利用
- 必要画像が3枚以上ある場合は、可能な限りサブエージェントを複数使って並列化する。
- サブエージェントには、画像ごとの役割を分けて依頼する。例: `hook + CTA`、`section 1`、`section 2`、`section 3`。
- 各サブエージェントの成果物は、次の形で受け取る。
  - 画像の役割
  - 具体的な構図
  - 生成プロンプトまたは素材検索キーワード
  - 画面上の配置注意点
  - 避けるべき既視感・NG表現
- サブエージェントに同じ画像や同じ構図を重複して作らせない。必ず担当範囲を分ける。
- メインエージェントは、サブエージェントの案を統合し、最終的な画像生成、保存、Remotionコード反映、プレビュー確認を責任を持って行う。
- 画像生成ツールがメインエージェントでしか使えない場合でも、サブエージェントにはプロンプト設計・構図案・表示注意点を並列で任せる。

## 画像ソース選択
- まず既存の `public/viral/<project>/` と `public/assets/channels/` を確認し、今回の台本に合うか判断する。
- 既存素材が台本に合わない、または過去動画と同じ印象になる場合は新規素材を取得または生成する。
- イラスト取得では、用途に応じて repo の画像取得系スキルを使う。候補が複数ある場合はユーザー確認を取る。
  - 日本語向けで親しみやすい絵: `tyoudoii-illust-fetcher`
  - Web/LP寄りで海外テイストの絵: `themeisle-illustration-fetcher`
- 写真素材が必要な場合は、フリー素材サイトを確認し、利用条件に問題がないものだけ保存する。
- 台本固有の構図が必要な場合、または素材サイトでは既視感が強い場合は画像生成を使う。
- Codex で画像生成を使う場合は、repo の画像生成ルールに従う。APIや課金APIは、ユーザーが明示した場合だけ使う。
- 生成画像を使う場合は、AI生成画像であることが必要に応じて分かるよう、ファイル名や報告で区別する。

## 画像保存・命名
- 保存先は原則 `Remotion/my-video/public/viral/<project>/`。
- 画像ファイル名は ASCII にする。例: `hook_memo_desk.png`, `s1_commute_back.jpg`, `s2_resume_numbers.png`。
- 生成元や検索元のメモが必要なら、同じフォルダの `asset_sources.md` に短く残す。
- 新しい素材を作った場合は、既存素材と混ざっても用途が分かる名前にする。
- 空データや取得失敗した HTML を画像として保存しない。保存後にファイル形式とサイズを確認する。

## 画面バランス・リサイズ
- 画像は 1080x1920 の縦画面で、タイトル・字幕・CTA と重ならないように表示する。
- 写真は横長でも幅 85-92% を基準にし、`objectFit: "cover"` と `objectPosition` で主題を中央に置く。
- イラストは余白が多いものがあるため、`getVisualScale` の補正やコンテナ側サイズで見た目の占有率を揃える。
- 画像の下端と字幕上端の間に最低 50px 以上を確保する。
- タイトルと画像は近づけるが接触させない。目安は 40-120px。
- 代表フレームを少なくとも、フック、各章開始、各章中盤、CTAで確認する。
- 画面確認で小さすぎる、切れすぎる、字幕と重なる、主題が見えない場合は、素材差し替えか表示設定の調整を行う。

## 効果音ラボの取得ルール
- 参照元: `https://soundeffect-lab.info/sound/anime/`
- 直リンク取得は 403 になることがあるため、`curl` では User-Agent と Referer を付ける。

```bash
curl -L -A "Mozilla/5.0" -e "https://soundeffect-lab.info/sound/anime/" \
  "https://soundeffect-lab.info/sound/anime/mp3/news-title1.mp3" \
  -o "$TEAM_INFO_ROOT/Remotion/my-video/public/audio/[project]/sfx/news-title1.mp3"
```

取得後は必ず `file "$TEAM_INFO_ROOT/Remotion/my-video/public/audio/[project]/sfx/*.mp3"` で、HTML ではなく `MPEG ADTS` などの音声ファイルになっているか確認する。

## 選定基準
- フック直後: `ニュースタイトル表示`、`タイトル表示`、`文字表示の衝撃音`。
- 場面転換: `シーン切り替え1/2`。章の開始、CTA への移行に使う。
- 痛み/違和感の強調: `グサッ2`、`ショック2`。多用しない。
- ビジネス・転職系では、コミカルすぎる `間抜け`、過度なホラー、長いファンファーレは原則避ける。
- ナレーションが主役なので、音量は `0.16` から `0.42` 程度で始め、聞き取りを邪魔しない。

## テンポ設計
- 冒頭 0-4 秒は、フックを即表示し、1回は強い視覚/音の切り替えを入れる。
- 章開始時は場面転換音を入れ、タイトルを見せてから本文に入る。
- 字幕が切り替わるタイミングでは、同じ写真を固定し続けず、イラスト/写真/別構図を切り替える。
- 新しいショート動画では、過去ショートの画像素材を使い回さない。字幕ごとに切り替える画像は、台本に合わせて新規生成するか、いらすとや等のイラスト素材、または利用条件を満たすフリー素材サイトから新規取得する。
- 過去作から引き継いでよいのは、画像サイズ、位置、余白、ズーム量、切り替えテンポなどの編集設計だけ。画像ファイル、素材フォルダ、staticFile の参照は新しい動画専用のものへ差し替える。
- 代表 still の確認時は、画像が過去作の雰囲気に寄りすぎていないか、今回の台本固有の要素が画面に出ているかも見る。

## テンプレ別基準の更新
- ユーザーが「もっとこうして」と言った内容は、該当テンプレートの基準ファイルへ短く追記する。
- 追記先が不明なら `references/templates/viral-short-vertical.md` に追加し、後で専用テンプレへ分割する。
- 変更前後の still を残し、どの基準を満たすための変更か最終報告に含める。
