# 開発の進め方

AI に頼んで作業するときの基本の流れです。

```text
最新を確認する
モードを確認する
作業する
こまめに commit する
チームへ反映する
必要なら Discord に報告する
```

## 1. 最新の状態にする

```text
/pull
```

Claude Code は `SessionStart` hook で、その日の初回だけ自動確認します。
Codex / Gemini など hook 未対応の環境では、会話の最初に手動相当の `/pull` を行います。

`/pull` は、まず `git fetch origin` を行います。
`origin/main` に更新があるときだけ `pull --rebase` を行います。
未コミット変更がある場合は、一時退避してから同期し、終わったら戻します。

## 2. モードを確認する

```text
/team
/personal
```

チームに共有する作業なら `team`、自分だけの下書きや試作なら `personal` を使います。
新規ファイル・フォルダを作る前は、AI が `.dev-mode` を読み、現在のモードをユーザーに確認します。

個人モードでは、新しく作るファイルは原則 `personal/<account>/` 配下に置きます。
`<account>` は Git アカウント名をもとに決まります。

既存ファイルを直すだけなら、このモード確認は不要です。

## 3. 作業する

作りたいもの、直したいこと、確認したいことを自然文で頼みます。
AI は既存のコード規約、フォルダ構成、スキルの手順に合わせて作業します。

Web アプリや LP など画面があるものは、可能な範囲でブラウザ表示と主要操作も確認します。

## 4. こまめに保存する

```text
/c
```

区切りがついたら commit します。
`/c` はチームへ push しません。

コミット前には、AI が差分を確認し、変更内容とコミットメッセージ案を出します。
ユーザーが承認してから commit します。

## 5. チームへ反映する

```text
/git
/git-nd
```

`/git` と `/git-nd` は、commit 後にリモートへ反映します。

| パソコンの種類 | 何が起きるか |
|-------------|------------|
| オーナー機 | `main` に直接 push する |
| それ以外 | GitHub アカウント名入りの作業ブランチを push し、`main` 宛ての PR を作る |

push 判断では、ユーザーに「オーナー機ですか」と聞きません。
`team_info_runtime.py owner-status` の結果で判定します。

push 前には Git LFS 無料枠チェックも行います。
無料枠を超えそうな場合は push せず、原因と対処を説明します。

## 6. Discord 報告

`/git` は、push / PR が終わったあと Discord 報告を送るか確認します。
送る場合は `discord-git-report` で報告します。
Webhook が未設定の場合は、Git の反映は成功として扱い、Discord 送信だけスキップします。

`/git-nd` は Discord 報告を送りません。

## 7. よくある注意点

- `.gitignore` はユーザーが明示しない限り変更しません。
- 既存の未コミット変更は、ユーザーや別作業のものとして扱い、勝手に戻しません。
- 削除、外部送信、環境設定変更など影響が大きい操作は、先に確認します。
- Docker / VOICEVOX など常駐系は、必要なときだけ起動し、使い終わったら止めます。
- 新しいスキルを足したら `.agent/skills/skill-finder/SKILL.md` も更新します。
